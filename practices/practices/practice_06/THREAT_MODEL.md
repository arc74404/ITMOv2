## Модель Угроз

Цели и активы
- Профили пользователей (PII), заказы, квитанции (files/<user>/receipt.txt).
- Служебная записка оператора (private/operator-note.txt), журналы.
- Токены сессий.

Акторы
- Внешний анонимный пользователь (без сессии).
- Клиент с ролью customer (владелец собственных данных).
- Сотрудник с ролью staff (оператор).

Поверхности атаки
- HTTP API: /login, /profile, /search, /orders, /admin/export, /files, /reviews, /reviews/view, /debug/logs, /assistant/*.
- Подсистема ассистента (context + execute) с инструментами: read_file, export_profiles, delete_tree.
- Журналы запросов.

Ключевые угрозы
- Инъекции SQL (параметры query в SQL).
- Горизонтальная эскалация привилегий (чтение чужих профилей/заказов/файлов).
- Вертикальная эскалация через доверие к заголовкам (X-Role).
- Манипуляция данными (цены заказов со стороны клиента).
- XSS/HTML injection и prompt injection через отзывы в HTML и в контекст ассистента.
- Незащищённый доступ к чувствительным служебным данным через инструменты ассистента.
- Утечки через /debug/logs.

Границы и допущения
- Процесс слушает 127.0.0.1, без исходящих сетевых вызовов.
- Файловая песочница sandbox.py задаёт физические пределы; ломать её нельзя.

Митигирующие меры (реализованы в фиксе)
- Параметризованные SQL-запросы и проверка ввода.
- Обязательная сессия и контроль владельца данных; RBAC только сессией.
- Игнорирование клиентской цены, сервер использует каталог.
- Экранирование HTML в /reviews/view.
- Ограничение /debug/logs ролью staff.
- Ограничение инструментов ассистента по роли и владельцу; файловые операции только в своём каталоге для customer.
