# Отчёт 1. Атаки на исходный сервис

Ниже — список найденных уязвимостей в исходном «дырявом» сервисе с примером эксплуатации и риском. Все данные учебные, атаки проводились в рамках локального стенда.

1. SQL Injection в /profile и /search
Описание: значения query-параметров напрямую подставлялись в SQL: `SELECT * FROM profiles WHERE id = {id}`, `name LIKE '%{q}%'`.
Эксплойт: `/profile?id=1 OR 1=1` возвращает все профили; `/search?q=%' OR '1'='1` раскрывает всю таблицу.
Риск: раскрытие персональных данных.

2. Отсутствие авторизации и контроля владельца
Описание: многие эндпоинты не требовали сессии и не ограничивали доступ по владельцу: `GET /orders` выдавал все заказы, `GET /profile` принимал произвольный id.
Эксплойт: незалогиненный пользователь видит все заказы; залогиненный «alice» запрашивает профиль `id=2` и получает «bob».
Риск: утечки данных между клиентами.

3. Повышение привилегий через X-Role
Описание: `/admin/export` проверял произвольный заголовок `X-Role` без привязки к сессии.
Эксплойт: `GET /admin/export` с `X-Role: staff` от любого клиента возвращает весь экспорт.
Риск: несанкционированный доступ к административным операциям.

4. Подделка цены заказа (trust on client)
Описание: при `POST /orders` клиент мог прислать поле `price`, которое сохранялось как есть.
Эксплойт: тело `{ "product": "chair", "price": 1 }` создаёт заказ со стоимостью 1.
Риск: финансовые потери, нарушение целостности данных.

5. Неправильный доступ к файлам пользователей
Описание: `GET /files` принимал параметры `user` и `path` без проверки сессии и владения, что позволяло читать чужие файлы; также возможно чтение служебной заметки через инструменты ассистента.
Эксплойт: незалогиненный `GET /files?user=bob&path=receipt.txt`; ассистент `read_file("private/operator-note.txt")` раскрывает секрет.
Риск: утечки, разрушение данных при комбинации с delete_tree.

6. HTML Injection/XSS в /reviews/view
Описание: отзывы рендерились без экранирования в HTML.
Эксплойт: `POST /reviews` с текстом `<script>alert(1)</script>` — вставка в HTML-страницу.
Риск: XSS, prompt injection против внешней модели судьи.

7. Неограниченный доступ к журналам
Описание: `GET /debug/logs` был доступен всем, включая тела и заголовки запросов.
Эксплойт: незалогиненный пользователь получает логи с токенами.
Риск: компрометация сессий и данных.

8. Инструменты ассистента без проверки полномочий
Описание: `/assistant/execute` выполнял `export_profiles`, `read_file`, `delete_tree` без проверки роли и владельца.
Эксплойт: клиент вызывает `export_profiles`; удаляет дерево чужих файлов; читает приватную заметку.
Риск: утечки, уничтожение данных в рамках стенда.

9. Журналирование до авторизации без маскирования
Описание: сервер записывает заголовки/тела целиком. В сочетании с «debug/logs» усиливает утечку.
Эксплойт: см. п.7.
Риск: рост поверхности утечки.

Модель угроз (кратко)
- Акторы: клиент (customer), сотрудник (staff), злоумышленник без логина.
- Атаки: SQLi, горизонтальная эскалация, XSS/prompt injection, несанкционированное выполнение инструментов, чтение журналов, манипуляция ценой, несанкционированный доступ к файлам.
- Активы: профили, заказы, квитанции, служебная заметка, токены.
- Границы: процесс на 127.0.0.1, файловая песочница от `sandbox.py` — соблюдены в изначальном коде.
