Выбранный SDD-фреймворк: Pact (Consumer-Driven Contracts)

Почему уместен здесь:
- В рамках фронтенд-проекта без серверного бэкенда мы используем Pact-образный подход для согласования контракта между UI (потребитель) и сервисом логики (провайдер) внутри TypeScript.
- Контракт формализован в виде TypeScript-типов и поведения промисов, а согласование отражено в specs/02_common_contract.md.

Сравнение с OpenSpec: см. общие мысли в предыдущем задании; ключевой вывод — Pact-подход лучше «заставляет» UI сначала описать потребности, а логику — подтвердить их тестами.
